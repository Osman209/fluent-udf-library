# ما الذي تغيّر؟

تم إصلاح الأساس الحالي للمكتبة، ولم تُضف حزم فيزياء جديدة بعد.

- حساب الإنثالبي أصبح تكاملًا متسقًا مع الحرارة النوعية داخل الجدول وخارجه.
- إشارة القص في طريقة تدرج السرعة أصبحت تمثّل قوة المائع على الجدار.
- متغيرات تتبع إعادة التشغيل أصبحت متوافقة مع Single وDouble Precision.
- الكتابة على الملفات مستبعدة من الـhost ومسموحة للعملية المختارة فقط.
- الجداول التالفة تُرفض بالكامل مع رقم السطر؛ العناوين تبدأ بعلامة #.
- موضع اتزان النابض ثابت وصريح، ولا يتغير عند تحميل حالة متحركة محفوظة.

## قبل تشغيل حالاتك القديمة

1. في `motion/sdof_spring_damper.c` اضبط `SPRING_REF_X` و`SPRING_REF_TH`
   على موضع واتجاه الاتزان الفيزيائي. الافتراضي صفر. لا تنسخ موضع الجسم
   المنزاح من ملف الاستكمال باعتباره الاتزان.
2. أعد بناء ملفات UDF المعدّلة مع نسخة `common/udf_common.h` الجديدة.
3. راجع رسائل تحميل الجداول. عند فقد ملف أو رفضه ما زالت القيم البديلة
   القديمة مستخدمة؛ نجاح بدء الحل لا يعني نجاح تحميل الجدول.
4. قارن القوى والعزوم بتقارير Fluent؛ تصحيح الإشارة يغيّر نتائج القص السابقة.
5. استخدم مجلدًا منفصلًا لكل تجربة لتفادي تداخل ملفات التسجيل.

## اختبار خارج Fluent

```sh
python3 -m pip install -r validation/requirements.txt
sh tests/run_tests.sh
```

الأوامر تحتاج gcc وبيئة sh مثل Linux أو WSL على Windows.
اختبارات الـmock ليست بناءً أو تشغيلًا داخل Fluent.

## التوسع المنظم

- `catalog/udfs.json`: فهرس الملفات وأسماء الدوال وحالة التحقق.
- `docs/validation-status.md`: الأدلة المتوفرة والحدود التي ما زالت قائمة.
- `examples/wavetank/README.md`: إعداد حوض مرجعي وخطوات ومعايير قبول مقترحة.
- `examples/wavetank/validation-record.json`: سجل يملأ بنتائج Fluent الفعلية.

هذه النسخة لم تُشغّل داخل Fluent في بيئة المراجعة. لا توجد ملفات case/data
موثّقة جديدة، ولا يُدّعى اعتماد التوازي أو إصدار Fluent بعينه.
